1 · 索敌在 Tick 管线中的位置

整段代码运行在 ABattleFrameBattleControl::Tick(float DeltaTime) 内，由 UE 引擎 Actor Tick 机制驱动，没有中间调度器。Tick 函数由若干 #pragma region 组成的串行阶段构成；索敌处于"空间数据就绪后、攻击决策前"的中游位置：

┌─ Statistics // 统计计数 ├─ Appear // 出生 / 入场 ├─ Sleep // 休眠状态机 ├─ Patrol // 巡逻状态机 ├─ Chase // 追击状态机 ├─ Move // 移动 / 转向 / 寻路 ├─ Update NeighborGrid // 重建空间格 ├─ Trace (L1472–L2006) // 本文主角 ├─ Attack Trigger // 读 Tracing.TraceResult 决定开打 ├─ Hit // 命中 / 伤害 └─ ... // 动画 / 抛射物 / 事件出队

为什么放在这个位置？

  • 上游 Move → Update NeighborGrid 已经把 FLocated / FDirected 更新到本帧最新，并重建了空间索引；索敌可以直接复用最新位姿。
  • 下游 Attack Trigger 需要消费 FTracing.TraceResult 才能决定是否进入攻击；索敌必须先写完结果。

2 · 两阶段并行结构（Gather → Trace）

区块内部其实是 两个并行阶段，中间通过 ValidSubjectsArray 数组桥接：

┌─────────────────────────────────────────┐ Phase A│ Chain->OperateConcurrently (筛选 + 冷却) │ 遍历所有匹配 AgentTraceFilter 的 agent │ ├─ 判断 MoveState │ 状态判断 + Tracing.TimeLeft 扣减 │ ├─ 写 ValidSubjectsArray[ThreadId] │ 按线程分桶 + per-bucket lock │ └─ 入队 OnTraceQueue (Begin 事件) │ └─────────────────────────────────────────┘ │ ▼ 合并所有桶 → ValidSubjects ┌─────────────────────────────────────────┐ Phase B│ ParallelFor (真正的检测) │ 只在子集上做重计算 │ ├─ switch (MoveState) 选参数 │ │ ├─ switch (ETraceMode) 执行检测 │ │ │ ├─ TargetIsPlayer_0 │ 高度→距²→角度→可见性 4 关 │ │ └─ SectorTraceByTraits │ NeighborGrid 扇形查询 │ ├─ 写回 Tracing.TraceResult │ │ ├─ 入队 OnTraceQueue (Succeed/Fail) │ │ └─ 失败时 SetTraitDeferred(FPatrolling) │ └─────────────────────────────────────────┘ │ ▼ Mechanism->ApplyDeferreds()
为什么要分两步？
第一阶段是 ECS 链上的轻量过滤：状态判定 + 冷却扣减，必须遍历整个 AgentTraceFilter。
第二阶段是潜在重操作：空间查询 + 可选可见性 raycast，只在筛出的子集上执行 — 这样把昂贵的工作量精确投放在需要的 agent 上。
此外 ValidSubjectsArray 按线程 ID 分桶（Index = ThreadId % ThreadsCount），每个桶自带锁，避免单一全局锁竞争。

关键代码：Phase A 的桶式收集

// L1503–L1508  建链 + 计算并发参数 + 准备分桶
auto Chain = Mechanism->EnchainSolid(AgentTraceFilter);
Chain->Retain();
UBattleFrameFunctionLibraryRT::CalculateThreadsCountAndBatchSize(
    Chain->IterableNum(), MaxThreadsAllowed, 200, ThreadsCount, BatchSize);

TArray<FValidSubjects> ValidSubjectsArray;
ValidSubjectsArray.SetNum(ThreadsCount);

// L1568–L1578  把"该索敌"的 agent 放进对应线程的桶
if (bShouldTrace) {
    uint32 ThreadId = FPlatformTLS::GetCurrentThreadId();
    uint32 Index = ThreadId % ThreadsCount;
    if (LIKELY(ValidSubjectsArray.IsValidIndex(Index))) {
        ValidSubjectsArray[Index].Lock();
        ValidSubjectsArray[Index].Subjects.Add(Subject);
        ValidSubjectsArray[Index].Unlock();
    }
}

每个 agent 在不同移动状态下采用 不同的索敌参数槽（同一份 FTrace 配置里挂着多套 FSectorTraceParamsSpecific）。下表整理 Phase A 的"是否启动"开关与 Phase B 的"用哪套参数"对照：

保底参数 (L1772–L1781)：在 Phase B 选参数时，若当前状态匹配但其专属参数槽 Params.bEnable == false，则 bIsParamsSet 保持 false，最后回落到 Common 槽 — 保证只要 bCanTrace 为真就一定有可用参数。

关键代码：Phase A 的 switch + 冷却推进

// L1517–L1567
if (Trace.bEnable && !bHasAttacking) {           // 攻击中不索敌

        switch (Moving.MoveState) {

        }
    } else {
        Tracing.TimeLeft = FMath::Clamp(Tracing.TimeLeft - SafeDeltaTime, 0, FLT_MAX);
    }
}

4 · 两种 ETraceMode 的检测路径

路径 A：ETraceMode::TargetIsPlayer_0

不走空间索引，直接对 UGameplayStatics::GetPlayerPawn(World, 0) 做四关筛选：

  1. 高度：PlayerLocation.Z - Located.Location.Z ≤ FinalHeight
  2. 距离²：DistSquared ≤ Square(FinalRange)（避免开方）
  3. 角度：Acos(Dot(Directed.Direction, ToPlayerDir)) ≤ FinalAngle / 2
  4. 可见性（可选）：UKismetSystemLibrary::SphereTraceSingleForObjects 检查 obstacle 阻挡 — 起点为自身，终点为 玩家表面点（已扣除玩家半径）

玩家有效性在 Phase B 进入前就预取：

// L1481–L1500  预取玩家句柄（每帧一次，所有 agent 共享）
APawn* PlayerPawn = UGameplayStatics::GetPlayerPawn(CurrentWorld, 0);
if (IsValid(PlayerPawn)) {
    USubjectiveActorComponent* C = PlayerPawn->FindComponentByClass<USubjectiveActorComponent>();
    if (IsValid(C)) {
        PlayerHandle = C->GetHandle();
        if (PlayerHandle.IsValid()
            && !PlayerHandle.HasTrait<FDying>()
            &&  PlayerHandle.HasTrait<FLocated>()
            &&  PlayerHandle.HasTrait<FHealth>()
            &&  PlayerHandle.GetTrait<FHealth>().Current > 0) {
            PlayerLocation = PlayerPawn->GetActorLocation();
            bPlayerIsValid = true;
        }
    }
}

路径 B：ETraceMode::SectorTraceByTraits

委托给 UNeighborGridComponent::SectorTraceForSubjects（声明于 Public/NeighborGridComponent.h:177），一次性完成：扇形几何 + Trait 过滤 + 可选 obstacle 可见性 + NearToFar 排序。

// L1930–L1948
Tracing.NeighborGrid->SectorTraceForSubjects(
    1,                  // KeepCount: 只要最近 1 个
    Located.Location,   // 扇形原点
    FinalRange,         // 半径 (= Collider.Radius*Scale + Params.TraceRadius)
    FinalHeight,        // 高度限制
    TraceDirection,     // 朝向 (Directed.Direction.GetSafeNormal2D)
    FinalAngle,         // 张角
    bFinalCheckVisibility,
    Located.Location, 0,
    ESortMode::NearToFar,
    Located.Location,
    IgnoreList,         // 含自身
    Trace.Filter,       // FBFFilter: include/exclude traits + obstacle object types
    DebugConfig,
    Hit, Results);

对比：路径 A 自己手写扇形数学（因为玩家通常不在 NeighborGrid 注册），路径 B 复用空间索引以 O(候选近邻) 替代 O(全部 agent)。

6 · 事件出口与调试出口

整个区块跑在并行环境，不能直接调用 BP 事件或 DrawDebug。所有"会触达游戏线程"的副作用都走队列：

队列入队点出队 / 消费
OnTraceQueue : FTraceDataL1586 (Begin)、L1987 (End_Succeed / End_Fail)Tick 末尾 L4167–L4181 出队 → IBattleFrameInterface::Execute_OnTrace(Actor, Data)（蓝图钩子）
DebugLineQueue / DebugSphereQueue / DebugCapsuleQueue / DebugPointQueue / DebugSectorQueueL1606 / L1613 / L1900 / L1909 / L1977统一调试绘制阶段（同一 Tick 末尾），在游戏线程上 DrawDebug*
 
// L1581–L1587  Begin 事件（在 Phase A）
if (bHasIsSubjective) {
    FTraceData TraceData;
    TraceData.SelfSubject = FSubjectHandle(Subject);
    TraceData.State       = ETraceEventState::Begin;
    OnTraceQueue.Enqueue(TraceData);
}

// L1981–L1988  End 事件（在 Phase B 完成后）
if (bHasIsSubjective) {
    FTraceData TraceData;
    TraceData.SelfSubject = FSubjectHandle(Subject);
    TraceData.State       = bHasValidTraceResult
        ? ETraceEventState::End_Reason_Succeed
        : ETraceEventState::End_Reason_Fail;
    TraceData.TraceResult = bHasValidTraceResult ? Tracing.TraceResult : FSubjectHandle();
    OnTraceQueue.Enqueue(TraceData);
}
为什么三态事件？
Begin 在 Phase A 决定要索敌时立即广播（即使最终没命中也会发），方便蓝图做"开始扫描"动画 / 音效；
End_Reason_Succeed / End_Reason_Fail 携带最终命中结果，蓝图据此决定切换 AI 状态或反馈。

7 · 命中后的副作用与下游消费链

写回

  • 命中：Tracing.TraceResult = Results[0].Subject 或 PlayerHandle
  • 未命中：Tracing.TraceResult = FSubjectHandle()（即先 reset 再可能赋值）

失败回退到巡逻 (L1992–L1999)

const bool bShouldPatrol = !bHasValidTraceResult
                          && !Subject.HasTrait<FPatrolling>()
                          && Patrol.OnLostTarget == EPatrolRecoverMode::Patrol;

if (bShouldPatrol) {
    FPatrolling NewPatrolling;
    ResetPatrol(Patrol, NewPatrolling, Located);
    Subject.SetTraitDeferred(NewPatrolling);     // 并行安全：延迟到 ApplyDeferreds
}

SetTraitDeferred 而非立即 SetTrait，是因为我们仍在 ParallelFor 内；整段结束时统一调用 Mechanism->ApplyDeferreds()（L2004）。
